# Audit Log and Task History Implementation Plan (FR-24 / M4-T4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement task change history on the task detail page (visible to project members, showing before/after changes and rejection/reopen reasons) and the system-wide `/admin/audit-log` page with actor, entity type, action, and date-range filters, newest first, 50 per page, restricted to Admins (FR-24 c1–4).

**Architecture:** Add `canViewAuditLog` policy, `AuditFiltersSchema`, and `AuditLogRow` DTOs in `@pm/domain`; extend `auditLogRepository` in `@pm/db` with `listByEntityWithActor` and paginated `listSystemLogs` (single `db.batch` for items + count using `idx_audit_entity` and `idx_audit_created`, mapping soft-deleted actors to `"Deleted user"` per `FR-03 c4`); add `auditLogService` and extend `taskService.getTaskDetails` to include `history`; create `adminAuditLogLoader.ts` and `_app.admin.audit-log.tsx`, and render the Task History timeline on `_app.projects.$projectId.tasks.$taskId.tsx`.

**Tech Stack:** React Router v8, Cloudflare D1, Drizzle ORM, Zod, Vitest, Playwright

**Spec:** `docs/01-srs.md` (FR-24, FR-03 c4), `docs/03-database-design.md` (`audit_logs`, `idx_audit_entity`, `idx_audit_created`), `docs/04-data-access-and-atomicity.md` (§6 paginated read batches), `docs/05-rbac-and-workflow.md` (§3.1, §3.2, §5.1), `docs/06-routes-and-actions.md` (§3.3, §3.4)

## Global Constraints
- System audit log (`/admin/audit-log`) is Admin-only; non-Admins (`PM`, `TEAM_LEAD`, `MEMBER`) receive `403` (`FR-24 c4`).
- Task history on `/projects/:projectId/tasks/:taskId` is visible to project members (`FR-24 c3`); non-members receive `404` (`P3`).
- Soft-deleted users render as `"Deleted user"` in audit rows (`FR-03 c4`); `null` `actor_id` renders as `"System"`.
- System audit log paginates 50 per page, newest first (`created_at DESC`), using one `db.batch` for items + total count (`docs/04` §6).
- Date-range filters (`from`, `to` in `YYYY-MM-DD`) use `getStartOfDayMs` and `getEndOfDayMs` in `APP_TIMEZONE`.

## Review Focus
- System `PM` (who passes `/admin` layout guard) opening `/admin/audit-log` -> receives `403` (`FR-24 c4`).
- Soft-deleted user's historical audit entries remain and show `"Deleted user"` (`FR-03 c4`).
- `TASK_CREATED` audit row records initial `changes` JSON (`title`, `priority`, `statusId`) alongside `TASK_UPDATED`, `TASK_STATUS_CHANGED`, `TASK_ASSIGNED`, `TASK_APPROVED`, `TASK_REJECTED`, `TASK_REOPENED`, `TASK_ARCHIVED` (`FR-24 c1`).
- Filtering `/admin/audit-log` by `actorId`, `entityType`, `action`, and `from`/`to` date range narrows results and preserves filter params across pagination links.
- Rejection and reopen reasons saved in `audit_logs.changes.reason.to` render clearly in Task History on the task detail page.
