# SSO Login Implementation Plan (M1-T7)

**Goal:** Implement Single Sign-On (SSO) with Google and Microsoft OAuth providers via `remix-auth`, link verified provider accounts to `oauth_accounts`, enforce user account matching and locking rules, and conditionally display SSO buttons only when configured (FR-02).

**Architecture:** Layered architecture adhering to AGENTS.md:
- Database: `oauth_accounts` table + migration `0004_oauth_accounts.sql`
- Repository: `oauthAccountRepository` (`findByProviderAccount`, `insertStmt`, `insert`)
- Service: `authService.loginWithOAuth`
- Routes: `/login` (conditional SSO buttons, error handling), `/auth/:provider` (OAuth start), `/auth/:provider/callback` (OAuth callback)
- Strategies: Mockable / configurable OAuth strategy integrated with `remix-auth`

**Tech Stack:** React Router v8, remix-auth, Cloudflare D1 (SQLite), Drizzle ORM, Zod, Vitest, Playwright.

**Spec:** `docs/01-srs.md` (FR-02), `docs/03-database-design.md` (oauth_accounts), `docs/06-routes-and-actions.md`.

---

## 1. Database & Repositories (`packages/db`)

- Schema `packages/db/src/schema/oauthAccounts.ts`:
  - `id`: text PK
  - `userId`: text FK -> users.id
  - `provider`: text CHECK in ('GOOGLE', 'MICROSOFT')
  - `providerAccountId`: text
  - `createdAt`: integer timestamp_ms
  - Unique index on `(provider, providerAccountId)`
- Migration `packages/db/migrations/0004_oauth_accounts.sql`.
- Repository `packages/db/src/repositories/oauthAccount.repository.ts`.

## 2. Service Layer (`apps/web/app/services/auth/auth.service.ts`)

- `loginWithOAuth(ctx: RequestContext, profile: OAuthProfile)`:
  - Normalize email: `profile.email.trim().toLowerCase()`
  - Find user by email (`userRepository.findByEmail`).
  - If user not found or deleted -> throw `ValidationError("No account exists for this email. Ask an administrator for an invite.")` (FR-02 c2).
  - If user `status === "LOCKED"` -> throw `ValidationError("This account is locked. Contact an administrator.")` (FR-02 c3).
  - If user `status === "ACTIVE"`:
    - Check if `oauthAccountRepository.findByProviderAccount` exists.
    - If not: insert `oauth_accounts` row.
    - Return `SessionUser` (FR-02 c1).

## 3. OAuth Helpers & Authenticator (`apps/web/app/services/auth/oauth.server.ts`)

- `getAuthenticator(env: Env)`:
  - Configures Google and Microsoft strategies if client ID and secret are present in `env`.
  - Strategy extracts providerAccountId and verified email from provider profile.

## 4. Routes & UI

- `apps/web/app/routes/login.tsx`:
  - Loader inspects `env.GOOGLE_CLIENT_ID` / `env.GOOGLE_CLIENT_SECRET` and `env.MICROSOFT_CLIENT_ID` / `env.MICROSOFT_CLIENT_SECRET`.
  - Returns `ssoProviders: OAuthProvider[]`.
  - UI renders Google / Microsoft sign-in buttons only for configured providers.
  - UI displays informative error banners for `?error=no_account` and `?error=locked`.
- `apps/web/app/routes/auth.$provider.tsx`:
  - Checks provider validity and credentials existence. If missing -> returns 404.
  - Redirects to provider authorization endpoint.
- `apps/web/app/routes/auth.$provider.callback.tsx`:
  - Authenticates callback, calls `authService.loginWithOAuth`.
  - On success: sets session cookie and redirects home (admin to `/admin`, member to `/`).
  - On error: catches `ValidationError` and redirects to `/login?error=no_account` or `/login?error=locked`.
