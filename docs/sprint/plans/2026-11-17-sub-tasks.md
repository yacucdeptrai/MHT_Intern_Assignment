# Sub-tasks Implementation Plan (FR-17 / M3-T7)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement sub-tasks functionality (FR-17) allowing project members to break top-level tasks into one-level sub-tasks, inherit parent's project and sprint, display "done / total" progress, and enforce permissions (P8) and one-level nesting.

**Architecture:** Update `taskService.createTask` to ensure sub-tasks inherit parent's sprint and use exact error string "Sub-tasks cannot have sub-tasks", wire `intent === "addSubTask"` in `taskDetailAction`, display sub-task progress and creation form in `_app.projects.$projectId.tasks.$taskId.tsx`, and verify with unit, route, and E2E specs.

**Tech Stack:** React Router v8, Cloudflare D1, Drizzle ORM, Zod, Vitest, Playwright

**Spec:** docs/01-srs.md (FR-17, P8, P12), docs/04-data-access-and-atomicity.md (A14), docs/05-rbac-and-workflow.md

---

## Acceptance Criteria Mapping
- **FR-17 c1:** Given a top-level task, When a member adds a sub-task, Then it is created with the parent's project and sprint, and the parent shows "done / total" sub-task progress.
- **FR-17 c2:** Given a sub-task, When anyone tries to add a sub-task beneath it, Then the request is rejected with 400 "Sub-tasks cannot have sub-tasks".
- **FR-17 c3:** Given sub-tasks, When permissions are checked, Then the same rules as for tasks apply (P8), evaluated on the sub-task itself.

---

### Task 1: Service Layer Updates & Tests
- In `taskService.createTask`:
  - When `data.parentTaskId` is provided, find `parent` and inherit `sprintId: parent.sprintId`. Any user-provided `sprintId` for a sub-task is ignored.
  - If `parent.parentTaskId` is not null, reject with 400 `ValidationError("Sub-tasks cannot have sub-tasks", { parentTaskId: ["Sub-tasks cannot have sub-tasks"] })`.
- Unit tests in `apps/web/test/task/task.service.test.ts`:
  - `FR-17 c1`: sub-task creation inherits parent's project and sprint.
  - `FR-17 c2`: adding sub-task to a sub-task throws 400 "Sub-tasks cannot have sub-tasks".
  - `FR-17 c3`: permission evaluation (P8) on sub-task (creator / assignee / lead can edit, other member receives 403).

### Task 2: Action & Route Layer
- In `apps/web/app/actions/taskDetailAction.ts`:
  - Handle `intent === "addSubTask"`.
  - Call `taskService.createTask(ctx, projectId, { ...rawData, parentTaskId: taskId })`.
  - Return `Response.json({ success: true, subTask }, { status: 200 })`.
  - Remove `TODO(M3-T7)`.
- Route tests in `apps/web/test/task/taskDetailRoute.test.ts`:
  - `FR-17 c1`: member adding sub-task via action succeeds and returns 200 with new sub-task.
  - `FR-17 c2`: attempting to add sub-task to a sub-task returns 400 "Sub-tasks cannot have sub-tasks".
  - Non-member receives 404.

### Task 3: UI & E2E Layer
- In `apps/web/app/routes/_app.projects.$projectId.tasks.$taskId.tsx`:
  - Compute `doneSubtasksCount = subTasks.filter((st) => st.statusCategory === "DONE").length` and `totalSubtasksCount = subTasks.length`.
  - Display progress badge/text `<span data-testid="subtask-progress">{doneSubtasksCount} / {totalSubtasksCount} done</span>` when `totalSubtasksCount > 0`.
  - If `!task.parentTaskId`, show "+ Add Sub-task" button toggling an inline form.
  - If `task.parentTaskId` is truthy (this task is a sub-task), do not render "+ Add Sub-task".
- Playwright E2E in `apps/web/e2e/subtasks.spec.ts`:
  - Member creates parent task in a sprint, adds sub-tasks.
  - Verifies sub-task inherits parent sprint and parent shows "0 / 2 done".
  - Verifies sub-task detail has no "+ Add Sub-task" button.
  - Verifies editing/archiving sub-task follows P8.
