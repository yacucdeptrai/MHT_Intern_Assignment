# M9-T1: Internationalization (i18n) Implementation Plan (NFR-06)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement full internationalization (Vietnamese default, English selectable) across the system, enforce missing-key and literal-string CI guards, support server-side rendering without hydration flicker, provide a seamless language switching experience, and support required error keys for user-facing errors.

**Architecture:** Bundle statically imported `en.json` and `vi.json` inside Workers with pinned `i18next` and `react-i18next`. Language selection is persisted in a client-readable `lang` cookie (`vi` default). The root loader reads the cookie and initializes a request-scoped i18n instance so SSR renders `<html lang="vi|en">` and translated strings immediately. The client initializes with the loader's language to prevent hydration mismatch. Errors carry canonical English strings and required translation keys (`errorKey`, `errorParams`, `errorKeys`).

**Tech Stack:** `i18next@27.2.1`, `react-i18next@18.0.2`, `eslint-plugin-i18next@6.1.5`, TypeScript strict mode with `CustomTypeOptions`, React Router v8 on Cloudflare Workers.

**Spec:** `docs/01-srs.md` (NFR-06), `docs/02-architecture.md`, `docs/10-implementation-roadmap.md` (M9-T1).

## Global Constraints

- **Exact pinned versions:** `i18next@27.2.1`, `react-i18next@18.0.2`, `eslint-plugin-i18next@6.1.5`. Zero `^` or `~`.
- **No runtime fetch:** Statically import JSON resource bundles (`apps/web/app/i18n/en.json` and `vi.json`). No HTTP or filesystem backend; runs strictly within Workers memory budget.
- **Isolate instance reuse:** Configure a base preloaded `i18next` instance at module load; create request-scoped instance via `cloneInstance({ lng })` or `changeLanguage` per request.
- **Default locale:** Vietnamese (`vi`); English (`en`) selectable. Any invalid or missing value defaults to `vi`.
- **Cookie storage:** Cookie name `lang`, `Path=/`, `SameSite=Lax`, `Max-Age=31536000` (1 year), `HttpOnly: false` (client switcher access), `Secure` on HTTPS.
- **Canonical server errors:** English error strings from SRS remain canonical. Zero weakening or removal of existing test assertions.
- **Diacritics & native review:** All Vietnamese strings drafted with proper tone marks and accents, cataloged under "Needs native review" in the PR.
- **Emails and Slack:** Remain English per `docs/07` §5 & §7 (recipient's language preference is out of scope).

## Approved Error Handling Architecture (Option A, Amended)

1. **`AppError` and subclasses**:
   - Keep canonical English `message` as the 1st argument (existing tests stay valid).
   - Require a translation key for user-facing errors:
     `new ValidationError(message, { key: "errors.status_in_use", params: { count } })` or `new ForbiddenError(message, { key: "errors.project_archived" })`.
   - Exceptions (internal errors never shown to users) are registered in an explicit allow-list with a rationale.
2. **`handleActionError` and action payloads**:
   - Keep `message` and `errors` exactly as today.
   - Return `{ success: false, errors, message, errorKey, errorParams, errorKeys }`.
3. **UI rendering**:
   - Translates ONLY by key: `t(errorKey, errorParams)`. No fallback matching of English text. If key is missing, displays English message and CI missing-key test fails.
4. **Zod field messages registry**:
   - Central registry `{ key -> canonical English }` in `packages/domain/src/schemas/messages.ts`.
   - Schemas use registry's English text. Actions map field errors to keys through the registry.
   - Test verifies every message literal in `packages/domain/src/schemas` is in the registry (failing-before test required).
5. **Coverage test**:
   - Scans `apps/web/app` and `packages/domain/src` for every `new (AppError|ValidationError|ForbiddenError|NotFoundError|ConflictError|UnauthorizedError)(` and fails if one has no key (unless in allow-list).
